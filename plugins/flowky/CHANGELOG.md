# Changelog

## Unreleased

- The FlowKy VS Code extension's old guard hook keeps the plugin's guardrails quiet only when its
  script, `.flowky/hooks/flowky-guard.mjs`, is in the project as a plain file. An entry whose script
  is missing (for example a clone without `.flowky/`), or has a link in its place, runs no guard, so
  the plugin's own guardrails now run there.

## 0.4.0

The four guardrails, in the shared core (FlowKy Pro runs the same code):

- Duplicate guard: a symbol index the plugin builds itself at session start (TypeScript and
  JavaScript, Python, Go, Rust; incremental; 2.5 s budget; `.flowky/cache/index/`), and a
  PreToolUse check on Write, Edit and MultiEdit that pauses a write once when it defines a name
  already exported from another file of the same language family, with that file, line and first
  line; once per file and name per session. `note` mode: context only.
- Loop breaker: failed Bash and PowerShell commands are counted from PostToolUseFailure (and from a
  command line that prints its own non-zero exit status), per session and per sub-agent, per
  command and error; the third identical failure gives Claude the first error line of the output;
  the next identical run is paused once. Editing files does not reset the count; the same command
  succeeding, a different error, `/flowky:retry` or the message `flowky retry` do.
- Staleness line: the map and the index are rebuilt at each session start; one line says when the
  extension's committed map is behind the code, when the index is partial, or when HEAD moved
  during the session; silent otherwise.
- Config doctor: `/flowky:config-doctor`, the extension's nine checks plus ten more; diagnoses only.
- New hook events: UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure. A project that
  still wires the FlowKy VS Code extension's old guard hook keeps the plugin's guardrails quiet,
  and the doctor and the health check say how to remove it.
- `.flowky/config.json` gets a `guardrails` section that can only make them quieter.
- Faster tree scan (file sizes read 32 at a time).
- After an internal safety review: one shared reader for every project file (no link, no special
  file, size cap, inside the project), one git runner that a folder's git configuration cannot make
  run anything, one 8 s session-start deadline, a bounded config doctor.
- After an internal behaviour review: `/flowky:retry` runs (its permission line); a missing module
  or file is no longer taken for a network error; names are compared inside one language family; a
  "Generated by ..." banner no longer hides a file from the index, and the health check says how
  many files were left out and why; the health skill shows the report as printed and knows when
  the mods layer runs in the session; with the mods layer active, the context hint is shown once.
- After the second looks: the staleness line is also shown to you (once per session); stored error
  lines older than 24 hours are erased on disk, closed sessions included; a printed exit status above
  255 is ignored; every read of every plugin file is checked to go through the shared reader.

## 0.3.0

First release under the FlowKy name. The code comes from Autopilot Lite 0.2.2, an MIT plugin by the
same author, after two internal security reviews and the fixes that followed them; this history
starts again here, and the earlier one is not carried over. What changed from 0.2.2:

- Names: catalogue `flowky`, plugin `flowky`, skills `/flowky:map`, `/flowky:health` (the former
  doctor), `/flowky:handoff` and `/flowky:project-map`; the mods command is `/flowky`.
- Places: project state in `.flowky/cache/` (with its own `.gitignore` containing `*`, written
  first), project settings in `.flowky/config.json`. The plugin writes nothing else in `.flowky/`,
  which the FlowKy VS Code extension also uses.
- Move from the former name: at the first session start, old state in `.claude/autopilot/` is
  copied only when it carries a machine stamp (this plugin's never did, so nothing is copied), and
  nothing is deleted. The health check lists what is left as old Autopilot state, safe to delete.
- The health check also warns when FlowKy and FlowKy Pro are enabled together, and carries the
  independence notice.
- One shared core: the files listed in `core.json` are the only copy of the code FlowKy Pro also
  runs.
- Tests: the plugin suites are grouped in two test files; new tests for the move, the cache-only
  rule in a project that holds the extension's files, the FlowKy folder rules, the core contract
  and a network-free bundle.
